# 《计算机体系结构与硬件安全》课程大纲

> 本文件为《计算机体系结构与硬件安全》课**单课程落地文件**（传统课程清单·天津大学网络安全学院）；总规划见本目录 [README.md](./README.md)。
> 大纲蓝本：《计算机体系结构与硬件安全》课程教学大纲（教材补充稿）——3 学分 / 64 学时（授课 48 + 实验 16），网络空间安全"拔尖创新班"专业必修课。
> 融入定位：**M2 单元植入 + 实验融入（大纲原生内置）**——源大纲已将昇腾/CANN 写入第 4 章（现规划为 **● 昇腾/CANN 主讲章**，8 课时：AI 大模型诉求与 CPU 困境 → GPU/NPU 与 SPMD+SIMD/SIMT → Ascend 950 架构设计 → CANN 异构计算架构 → Ascend C 算子编程 → 调试调优实践，约 6 学时主讲）、第 7 章异构可信边界小节（7.3）与实验 1（昇腾运行基线与接口观测，全程 CANN 环境）；本文件保持传统主体（指令集 / 微架构 / 存储 / 硬件安全）不动。
> 课程特色：**体系结构 × 硬件安全双线贯穿**——每个体系结构机制都同时回答"对性能的影响"与"对安全边界的影响"两个问题；昇腾/CANN 在其中扮演双重角色：既是异构计算的当代架构实例（第 4 章），又是异构系统可信边界的分析对象（第 7 章）。

## 二、课程目标与课程内容规划

### 2.1 课程目标（四项，支撑毕业要求指标点）

| 课程目标 | 达成要求 | 支撑毕业要求 |
|---------|---------|------------|
| **目标 1**（占比 30%） | 理解指令集、处理器微架构、存储层次及并行与异构计算的基本原理，能够绘制关键数据通路，建立执行时间与访存性能模型，分析体系结构设计对性能和访问保护的影响 | 毕业要求 1"工程知识"指标点 1.2 |
| **目标 2**（占比 30%） | 能够识别处理器、存储和外设接口中的硬件安全威胁，明确资产、攻击者能力、攻击条件及信任边界；结合技术文献、执行轨迹和实验数据，分析侧信道、瞬态执行及物理攻击等风险，并比较防护思路的适用范围 | 毕业要求 2"问题分析"指标点 2.2 |
| **目标 3**（占比 30%） | 能够针对给定系统的性能瓶颈与安全需求，提出并实现一项缓冲、调度或访问控制改进，完成正确性、边界条件和异常响应验证，评价安全效果及性能、资源代价，形成有依据的软硬件设计方案 | 毕业要求 3"设计/开发解决方案"指标点 3.3 |
| **目标 4**（占比 10%） | 能够选用仿真、EDA 及 CANN 等工具开展体系结构建模、性能测量与安全测试，设计可重复的验证过程，形成代码、数据和技术报告，并说明工具、模型与测量结果的适用范围和局限 | 毕业要求 5"使用现代工具"指标点 5.2 |

### 2.2 结业能力画像

完成本课程后，学生将能够：

- **画得出**：绘制简化系统结构与关键数据通路，说明性能模型的假设，辨认程序数据和硬件资源的保护边界；
- **算得清**：计算 CPI、命中率、平均访存时间与加速比，判断流水线冒险，为设计改进建立定量依据；
- **辨得出**：建立硬件安全威胁模型（资产 / 攻击面 / 攻击者能力 / 信任边界），区分相关性、可利用的泄露证据与完整攻击结论；
- **改得动**：在教学 AI 加速器 RTL 基线上完成一项缓冲、调度或访问控制改进，并用回归测试与对照数据证明正确性、周期与资源代价；
- **说得明**：标注异构系统的可信计算基与信任边界，说明防护机制提供的保证与未覆盖的威胁，以及工具、模型与测量结果的适用范围和局限。

| 部分 | 章次 | 授课学时 | 内容主线 | 穿插实验 |
|------|------|---------|---------|---------|

### 3.2 领域前置（无硬性要求）

- 无 AI / 大模型背景要求——第 4 章昇腾样例由教师给定，从样例分析数据流即可；
- 建议实验 1 前预习 [quick_start/cann_basics](../../quick_start/cann_basics/)（`02_what_is_npu`、`03_what_is_cann`，约 30 分钟），建立 NPU/CANN 基本词汇。

### 3.3 环境前置

- **实验 1（昇腾实机）**：教师预先试做并固定 CANN 及驱动版本、授权算力与可用时段；安装及账号准备在课前完成；实机使用校内或远程昇腾环境，如只能提供教师运行轨迹，应明确该环节为分析替代，不计作学生实机操作；
- **实验 2—4（仿真环境）**：教师预先提供已试做的简化 RTL 基线、修改接口和测试集；教学硬件改动和边界测试由学生在仿真环境完成，FPGA 可作进阶验证；
- **测量纪律**：性能比较固定输入、预热和重复测量规则，保留原始记录及统计结果；昇腾耗时、RTL 周期和 FPGA 结果分别报告，不直接跨平台排名；TEE 和物理侧信道案例按实际设备能力选取。

### 4.2 第 1—3、5—8 章教学要点

**第 1 章 计算机体系结构与硬件安全概论（4 学时）**
- 1.1 体系结构的层次与接口：指令集体系结构、微体系结构和硬件实现；处理器、存储与外设的组成关系；软件与硬件的职责边界；
- 1.2 体系结构的评价方法：执行时间、CPI、吞吐率、加速比及 Amdahl 定律；性能、功耗与资源开销的基本含义；基准负载与公平比较条件；
- 1.3 硬件安全的基本问题：机密性、完整性与可用性；资产、攻击面、攻击者能力和信任边界；设计、制造、部署与运行阶段的安全风险；
- 重点为体系结构层次、性能模型和威胁模型；难点为把抽象安全目标落实到具体硬件状态、接口及保护条件。讲授结合结构图分析和定量练习。支撑目标 1、2。

**第 2 章 指令集与处理器微架构（8 学时）**
- 2.1 指令集与程序执行：以魏继增教材 MiniMIPS32 为教学实例，说明寄存器、指令编码、寻址方式、访存与控制转移；从简单程序追踪机器状态变化；
- 2.2 数据通路与流水线：运算部件、寄存器堆和控制逻辑；单周期与流水线处理器；结构、数据和控制冒险，以及旁路、停顿和分支预测；
- 2.3 指令级并行：超标量、乱序执行、寄存器重命名、推测执行和顺序提交的基本思想；体系结构状态与微架构状态的区别；
- 2.4 特权与异常：特权级、异常与中断、上下文切换、精确异常及权限检查；理解处理器状态转换中的隔离要求；
- 重点为指令语义、流水线控制和特权隔离；难点为解释指令提交与状态回滚，以及性能优化机制与安全边界的关系。以《计算机系统设计（上册）》为主要案例，采用指令追踪、结构图和波形推演；基于给定模型分析，不要求从零实现完整 CPU。支撑目标 1、2、4。

**第 3 章 存储系统与访问保护（8 学时）**
- 3.1 存储层次：局部性、Cache 映射、替换与写策略；命中率、平均访存时间、容量和带宽约束；Cache 与显式管理缓冲的区别；
- 3.2 虚拟存储与保护：地址转换、页表、TLB、缺页及读写执行权限；进程地址空间与共享存储；权限检查和地址转换的配合；
- 3.3 输入输出与设备访问：总线和内存映射 I/O、中断与 DMA；IOMMU 的地址转换和隔离作用；主机与设备共享数据时的访问范围与生命周期；
- 3.4 存储性能与安全约束：数据复用、缓冲组织与访存竞争；共享资源的可观测状态；隔离策略对命中率、带宽与等待时间的影响；
- 重点为存储层次分析及地址访问保护；难点为区分地址空间隔离与微架构资源隔离，并说明设备访问权限的来源和边界。结合地址转换练习、访存轨迹及实验 2 前半部分。支撑目标 1、2、4。

**第 5 章 微架构侧信道与瞬态执行安全（8 学时）**
- 5.1 微架构侧信道：共享 Cache、分支预测器及其他共享资源中的可观测状态；时间差异与信息泄露；攻击前提、噪声、混杂因素和证据边界；
- 5.2 瞬态执行风险：推测执行、权限检查、投机窗口及微架构残留；通过典型公开案例理解程序状态回滚后仍可能存在的可观测影响；
- 5.3 防护与评价：资源隔离、分区、状态清理、序列化和数据无关实现的基本思路；安全覆盖范围与性能代价；结合 AI 工作负载讨论模型和中间数据的泄露风险；
- 重点为微架构状态与泄露路径；难点为区分相关性、可利用的泄露证据和完整攻击结论，并根据具体架构判断缓解措施是否充分。采用文献导读、执行轨迹推演和实验 2 后半部分。支撑目标 2、3、4。

**第 6 章 物理攻击与硬件设计安全（4 学时）**
- 6.1 物理攻击概述：功耗与电磁泄露、故障注入的基本机理；物理接触能力、故障模型和攻击条件；与微架构侧信道的区别；
- 6.2 硬件设计及供应链风险：硬件木马的触发与载荷、第三方 IP 和制造测试环节的信任问题；调试与测试接口暴露，以及密钥和敏感状态保护；
- 6.3 防护与验证：冗余检测、错误检测、安全状态恢复和调试访问控制；设计审查、测试与追溯的作用和局限，强调单项检查不构成完整可信证明；
- 重点为物理与设计层威胁模型及对应防护；难点为区分随机故障和恶意扰动，以及检测能力与成本之间的取舍。以公开案例、简化故障模型和防护方案讨论为主，不另设设备攻击实验。支撑目标 2、3。

**第 7 章 可信计算与硬件安全机制（4 学时）**
- 7.1 硬件信任根与启动链：可信根、密钥存储和基础密码功能；安全启动与度量启动的区别；启动链验证、更新与回滚风险；
- 7.2 可信执行与远程证明：可信执行环境的隔离目标、可信计算基和远程证明过程；证明结果的含义与局限；侧信道和不可信外设带来的影响；
- 7.3 异构系统可信边界（◐ 昇腾对照）：CPU 与 AI 处理器协同中的模型、输入及中间数据保护；设备内存、可信 I/O、密钥释放与状态清理；软件、固件和硬件的协同责任；
- 重点为信任链、隔离和证明机制；难点为区分身份或状态证明与运行期安全保证，分析主机侧保护无法自动覆盖设备侧的原因。通过启动链、证明流程和异构系统结构图进行案例分析。支撑目标 1、2、3。

**第 8 章 体系结构与硬件安全综合设计（4 学时）**
- 8.1 从需求到设计：把资产保护、访问范围、异常行为和性能约束转化为可验证要求；选择隔离、访问检查及状态清理的实现位置；
- 8.2 软硬件协同验证：功能基线、边界测试、异常与复位测试、回归测试；采用仿真和观测数据解释设计差异，并说明测试覆盖范围；
- 8.3 综合方案评价：结合教学 AI 加速器的前期改动，比较防护效果、执行周期、吞吐率及资源代价；讨论失败用例、替代方案和剩余风险；
- 重点为安全需求、设计实现和验证证据的对应；难点为在有限资源下兼顾保护效果与性能，并避免把测试通过等同于无条件安全。结合方案评议、实验 4 及大作业汇报。支撑目标 2、3、4。

| 1 | **AI 时代对体系结构的挑战——为什么需要异构计算？** | ① AI 大模型对计算和存储的新诉求：计算维度——大规模矩阵乘主导、算力与能效需求指数级增长；存储维度——海量权重与 KV Cache 的带宽 / 容量压力；算子 DAG 与算力—带宽失配（Roofline 视角）；② 传统 CPU 架构为何无法应对：通用核晶体管大量分配给 Cache 与控制、缓存层次对大模型权重流失效、功耗墙与 Amdahl 定律限制，缓存一致性与同步开销对多核并行的制约（传统并行知识点在此融入）；结论：负载分化驱动架构演进，异构计算 = CPU 指挥、专用加速器演奏 | ◐ |

| 6—7 | **NPU 的算子编程——Ascend C 算子编程语言** | 如何基于 NPU 自定义开发计算任务：**Ascend C 以 SIMD 为主、SIMT 为辅的编程模型**：SIMD 核函数、SIMT 核函数与混合编程；**编程 API**：Tensor API、C API介绍与选型；**Reg 矢量与矩阵编程**：Reg 矢量编程、矩阵编程；矢量算子全流程跟练：Host 初始化 → DataCopy 搬入 → 计算 → 搬出；**架构到代码的映射**：每条语句驱动哪个硬件单元、数据流经哪级存储——课时 3—4 架构概念的代码落地 | **●** |
| 8 | **Ascend C 算子调试调优实践与案例解析** | 如何对算子进行调试调优：调试调优流程与工具（精度比对；剖析采集 → 单元利用率 / 流水图 → 瓶颈定位 → 优化验证）；优化方法论：Tiling 分块（UB 容量约束）、双缓冲流水、访存优化（对齐 / 布局 / 融合）；**Ascend C SIMD 与 SIMT 算子调试调优案例分析**：典型算子优化前后对照（瓶颈 → 改动 → 数据证据）；收束全章：体系结构原理 → Ascend 950 架构 → Ascend C 编程 → 观测优化的证据闭环 | **●** |

### 5.3 实验要点与约束

- **实验 1**：重点为建立可重复基线，难点为区分计算与传输阶段；安装及账号准备课前完成；提交运行记录和接口图（上机载体见 5.2 课时 5 行：`quick_start/first_operator_api_call`）；
