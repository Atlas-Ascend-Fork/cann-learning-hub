# 传统课程 · 《软件工程》：课程大纲

> 本文件为《软件工程》课**单课程落地文件**（传统课程清单·软件工程学科）；总规划见本目录 [README.md](./README.md)。
> 融入定位：**M2 单元植入 + 大作业融入**——传统软件工程八章主体不动（36 学时，第 1~12 周），第 13~14 周植入 **● Agentic AI Software Engineering 专题**（6 学时，2 次 × 3 学时）：AI 从被动的代码生成工具，转变为能**自主规划、自主行动、自我适应**工程工作流的智能体，以 CANNBot（CANN 社区 Infra 智能体层）为教学案例，逐层解剖"具体如何实现"；第三部分以传统项目 ＋ **基于 CANNBot 的社区实践**双线大作业收束（第 15~16 周）。
> 课程主线：**同一套软件工程知识域的两种形态**——前十二章学"人做工程"的经典形态，第 9 章看"AI 团队做工程"的 Agentic 形态，每个新概念都能回链传统章节（SDLC ↔ 工作流 YAML、SRS ↔ 需求卡、IV&V ↔ 验收对偶、配置管理 ↔ PR 红线、过程资产 ↔ Skill 工程）。
> 开课成本：Agentic 专题讲义与实操素材**全部现成**（[tutorials/CANNBot](../../tutorials/CANNBot/README.md) 三阶段课程 + 9 门专题课件）；社区实践大作业无强制硬件依赖（文档工程型），开课门槛低。

## 二、课程目标与课程内容规划

### 2.1 三维目标

| 目标维度 | 达成要求 |
|---------|---------|
| **知识目标** | ① 掌握软件过程与生命周期模型（瀑布 / 增量 / 迭代 / 敏捷 / DevOps）、需求工程全流程、面向对象分析与设计（UML）、经典设计模式与架构风格、软件测试方法（黑盒 / 白盒 / V&V）、软件项目管理基础；② 理解 Agentic AI 范式：AI 从被动代码生成工具转变为能自主规划、行动和适应工程工作流的智能体；③ 掌握 CANNBot 的实现机制：Plugin / Agent / Skill 三层架构、工作流编排（过程即代码）、节点级验收对偶、Skill 知识工程与双流反哺 |
| **能力目标** | ① 能完成传统 SDLC 全流程文档与建模（SRS、UML 设计、测试计划、项目计划）；② 能撰写驱动 AI Agent 的需求规格（需求五要素 / 需求卡），判读验收证据并做出放行决策；③ 能以 Issue → PR / Skill 贡献形式参与开源社区实践 |
| **素养目标** | 建立"过程—质量—责任"的工程观；在 Agentic 时代坚守独立验收原则（AI 产出必须被独立验证）；建立人机分工的边界意识（按任务属性分配，而非按难度） |

### 2.2 结业能力画像

完成本课程后，学生将能够：

- **写得出**：合格的需求规格说明书（SRS）与 OO 设计模型（用例图 / 类图 / 时序图），以及驱动 AI Agent 的需求卡；
- **测得全**：设计覆盖功能 / 边界 / 特殊值的测试用例矩阵，读懂 golden 对拍与容差判据的验收报告；
- **管得住**：编制项目计划与风险清单，执行 Git 分支与 PR 配置管理流程；
- **指挥得动**：把需求说清楚、发起 Agentic 工作流、判读验收证据链、界定人机分工边界；
- **融得进**：以策略条目 / Issue / PR 的形式向开源社区（cannbot-skills）贡献一次可溯源的知识。

### 2.3 课程内容规划（三部分）

| 模块 | 周次 | 核心内容 | 关键产出 |
|------|------|---------|---------|
| 第一部分：传统软件工程主体 | 第 1~12 周 | 课程导论 → SDLC → 需求工程 → OO 设计与建模 → 设计模式 → 架构与设计 → 软件测试 → 项目管理（八章） | 传统作业 + 章节小项目 |

- 希望了解 NPU / Ascend C 背景的学生可选读 `tutorials/ascendc_operator_development_light/`（非必需——Agentic 专题中算子代码由 AI 团队编写，学生聚焦指挥与决策）。

### 3.3 环境前置

- **传统部分**：任意开发环境 + Git 仓库（沿用课程现有配置）；
- **第二部分课堂实操（第 14 周）**：三选一——CANNLab 云端开发环境（浏览器访问，推荐）/ 本地已部署 CANN ≥ 9.0.0 的昇腾环境（Atlas A2/A3）+ CLI 工具（OpenCode 等）/ cann-learning-hub 在线 Notebook（镜像 `cann_9.0.0_py3.11-A2-arm`）；**实机资源不足时降级为在线 Notebook 实录走读 + 验收报告判读**，不影响教学目标达成；
- **社区实践（大作业）**：GitCode 账号 + 个人访问令牌 + 一个 fork（任务 B 为文档工程，无任何硬件依赖）。

### 4.2 第二部分：Agentic AI Software Engineering 专题（6 学时，第 13~14 周 ● 主讲）

> 专题主线：**AI 从被动的代码生成工具，转变为能自主规划、行动和适应工程工作流的智能体——CANNBot 如何实现这一转变**。素材全部取自 [tutorials/CANNBot](../../tutorials/CANNBot/README.md)（阶段一~二为主）与 cannbot 主仓（v3.0.0）真实工程资产。

#### 第 1 次课（第 13 周）：范式转移与核心机制——"具体如何实现"的解剖（上）

| 时段 | 内容要点 | 教学法 | 素材 |
|------|---------|--------|------|
| 0~40' | **范式转移：从被动工具到自主智能体**：被动补全（人执行闭环）vs Agentic（Agent 执行闭环）；闭环五步（理解需求→写→执行→看结果→改→再执行→交付）；四维对比（能看什么 / 能做什么 / 怎么确认 / 交付物）；责任新命题——AI 产出必须被独立验证 | 讲授 + 对比表 | `01_basics/01.01_cannbot_basics.ipynb` §1 |
| 40~85' | **核心机制①——自主规划与自主行动**：Agent = 大模型 + 工具 + 自主决策；Skill = 按需加载的领域知识手册；多 Agent 协作与角色分离（架构师 / 开发者 / 性能编排者 / 验收者——编写代码的角色不能自行宣布测试通过）；三层架构（Plugin=菜谱 / Agent=厨师 / Skill=手册）：新增场景只需新增菜谱 | 讲授 + 三层架构图 | 01.01 §2；`cannbot/plugins-official/ops-direct-invoke/agents/`（四角色定义走读） |
| 85~135' | **核心机制②——过程即代码与工程工作流**：工作流 YAML = 可执行的过程模型（节点 DAG / 依赖与并行 / 验收标准内嵌 / 自动重试与回滚）——第 2 章 SDLC 的机器可执行形态；**自主适应与自愈**：执行者自检（加载 Skill 定位修复）、verifier 失败原因自动注入 + harness 自动重试、治理强度随风险缩放（Flash 11 分钟 vs 完整版 3.6 小时实录对比）；布置课前实操准备 | 讲授 + YAML 走读 + 实录数据 | `02_core_workflows/02.01_complete_workflow.ipynb`；`orchestrations/workflows/ascendc/basic.yaml`；`harness/workflow-orchestrator/` |

#### 第 2 次课（第 14 周）：CANNBot 案例实操与人机边界——"具体如何实现"的解剖（下）

| 时段 | 内容要点 | 教学法 | 素材 |
|------|---------|--------|------|
| 0~50' | **课堂实操：指挥 AI 团队交付第一个算子**：课前完成四步安装（Flash 版）；课中用需求五要素发起 add_custom → 观察八阶段推进（骨架先行 / 文档先行 / **测试先行** / 跳过留痕）→ 判读 17/17 位级一致验收证据；无环境者走读在线 Notebook 实录 | 实操 / 跟读 | `01_basics/01.02_flash_workflow.ipynb` §3~7 |

### 6.2 结业大作业（双线）

> 大作业由**一条传统主线 + 一条社区实践线**构成，均必选；前者检验经典工程能力，后者把能力延伸到"指挥 AI 团队 + 反哺开源社区"，两线在答辩时合流（传统项目也可选做"同一题目的两条实现路径"：人写 vs Agent 写，对比过程数据）。

| 作业 | 档位 | 内容 | 考核点 |
|------|------|------|--------|
| 作业 1 · 传统软件工程项目 | **必选**（传统主线） | 团队（4~5 人）选定题目走传统 SDLC：SRS（含非功能需求与验收标准）、OO 设计（UML 全套）、架构与模式选型说明、测试计划与执行报告、项目管理 artifacts（WBS / 风险矩阵 / 燃尽图）、Git 仓库与 PR 评审记录 | 文档规范性与一致性；UML 质量；测试覆盖设计；过程数据完整性 |
| **作业 2 · 基于 CANNBot 的社区实践（对接 CANN 官方社区任务）** | **必选（新增）** | **从 CANN 官方社区任务入口（<https://gitcode.com/org/cann/discussions/211>）浏览并认领一项真实社区任务**，按下方任务菜单四选一完成；进入社区任务前先完成**热身**（用 Flash 版独立交付 `sigmoid_custom`，五要素需求 + 验收证据，作为能力门槛），收尾时完成**边界自评**（用 AI 边界框架复盘"交给了 Agent 什么 / 留给了自己什么"）。任务菜单与考核点见下表 | 任务认领与提交凭证（PR / issue / 参赛记录）；所选类型对应考核点；通用纪律合规（GET 回查与双向关联证据）；热身验收证据真实可复现；边界自评深度 |
| 作业 3 · Agentic SE 边界评估报告 | 可选加分 | 用 AI 边界框架为自己团队 / 实验室的一个真实场景做 AI 化评估：适合 / 不适合交给 Agent 各一条判据（对照四条属性），并给出 ROI 三步走试点计划（试点场景 → 双重验证标准 → 推广条件） | 论述深度与判据可操作性 |

**作业 2 社区任务菜单（从官方入口认领，四选一或组合）**：

| 类型 | 内容 | CANNBot 结合方式 | 目标仓 / 完成凭证 |
|------|------|----------------|-----------------|
| **T1 · 算子开发**（推荐主线） | 认领一个算子开发任务（面向 A2 实现），按官方两阶段 PR 走：**设计文档 PR**（标题格式【社区任务】${算子名称}算子设计文档；含 TBE 与 Ascend C 流程图、算子原型、数据类型适配说明，对齐社区评审 CheckList）→ **算子代码 PR**；响应社区评审意见直至合入（真实评审常需多轮往返） | 用 CANNBot 完成算子初版生成 / 调试 / 优化（需求五要素发起、判读验收证据）；**设计文档、评审响应与合入决策由学生完成**——这正是传统需求/设计/评审知识在 Agentic 场景的实战 | cann/ops-math、cann/ops-nn 等算子仓 experimental 目录；PR 链接 + 评审往来记录 |
| T2 · 文档与样例改进 | 从 cann-learning-hub / cann-samples 等 issue 列表选题：文档改进、教程补充、算子样例、Bug 修复 | 可用 CANNBot 辅助生成初稿与核验，学生负责事实核验与规范对齐 | 对应社区仓；PR / issue 提交记录 |
| T3 · Skill 知识反哺（Agentic 特色） | 把实践中的一条实测经验按"实测依据 → 策略 → 纪律"三段式写成 Skill 策略条目，过 evals 与静态门禁后走 Issue→PR 提交（在自己 fork 上完成，须含 GET 回查与双向关联证据；质量不达标者可先以高质量 Issue 提交） | 直接反哺 CANNBot 知识层（双流闭环：一线经验 → Skill → 全体用户复用） | cannbot-skills 仓；Skill diff + 门禁验证记录 + PR 链接 |
| T4 · 社区竞赛 | 参加 CANN 算子天梯赛等社区打榜 / 竞赛活动 | 可用 CANNBot 辅助完成性能优化迭代（调优三原则 + 双回归） | 竞赛平台；参赛 / 获奖记录 |

> **通用纪律**（全类型适用）：内容源于代码、写操作前用户确认、写后 GET 回查、Issue↔PR 双向关联——即第 9 章所授 PR 八步与五条红线在真实社区的执行。**节奏建议**：社区任务存在评审周期，须**第 15 周前完成认领与首版提交**，为多轮评审往返预留时间；完成 T1 合入者另计入平时加分。

> 大作业可自学完成：[tutorials/CANNBot](../../tutorials/CANNBot/README.md) 三阶段课程（阶段一零基础 → 阶段二机制 → 阶段三进阶实战）提供全部实操指引；无算子开发基础者完成两项必选即可。

## 七、学习建议

- **第一部分"打地基"**：SDLC（第 2 章）、需求工程（第 3 章）、软件测试（第 7 章）三章是第 13~14 周专题课的对照基线——专题课的每个 Agentic 新概念都会回链到这三章的经典概念；
- **第二部分"迁移"**：听课主动做"旧知识 ↔ 新形态"连线（SRS↔需求卡、过程模型↔工作流 YAML、IV&V↔验收对偶、配置管理↔PR 红线、过程资产↔Skill 工程）——Agentic SE 不是新学科，是同一套软件工程知识域的新执行主体；
- **第三部分"合流"**：大作业两线并行——传统线检验"人做工程"的文档能力，社区实践线检验"指挥 AI 团队 + 反哺社区"的新能力；先完成作业 2 热身（sigmoid_custom 独立交付），再从官方社区任务入口认领任务——**第 15 周前完成认领与首版提交**，社区评审存在多轮往返，宜早不宜迟；
- **责任纪律**：全程贯彻"AI 产出必须被独立验证"——验收证据以亲手复验为准；社区实践全程适用五条红线，POST 返回 200 不等于任务完成，写后必 GET 回查；
- **延伸方向**：对 Agentic 工程方向感兴趣的同学，可继续 [tutorials/CANNBot](../../tutorials/CANNBot/README.md) 阶段三进阶自学（约 6.5 小时：gelu_approx 八步链的生成 / 调试 / 优化 / 反哺闭环）与 9 门专题课件（Harness 工程建设 / 算子测试全流程等）。
