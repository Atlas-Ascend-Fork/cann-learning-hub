# 4.6 参考答案

## 基础题

（1）B。SpMV 直接调用 `aclsparseSpMV`，最后的 workspace 参数为 `nullptr`，输出 `Workspace bytes=0 (API default workspace)`。GEMM 则先查询工作区并分配内存。

（2）对。先释放向量描述符，再释放矩阵描述符和 handle。已经创建的资源由 `SparseDescriptors`、`Workspace` 等对象管理，异常退出时也会释放。

## 运行与校验

运行一次 GEMM 或 SpMV，查看相对误差是否小于 `1e-6`。

## 数据流和资源

两种算子都先把输入复制到设备，执行算子，等待 Stream 完成，再回读结果。GEMM 用 Tensor、workspace 和 executor；SpMV 用 handle、CSR 描述符和向量描述符。

SpMV 输出中的 `Timing scope` 说明计时范围，没有独立的 H2D/D2H 时间。根据源码指出传输发生的位置，结合规模、误差、工作区和时间字段解释执行过程。本题比较调用与资源管理，两个不同数学任务的耗时不作为相互加速比。

## 错误分析

使用不存在的设备编号时，设备初始化应失败。保存实际 ACL 错误码、出错调用和程序退出码；不要预填固定错误码。结合 Runtime 源码列出失败前已创建的资源及清理顺序。将设备编号改回 0 后重新运行，确认后端和设备输出正确、相对误差小于 `1e-6`。
