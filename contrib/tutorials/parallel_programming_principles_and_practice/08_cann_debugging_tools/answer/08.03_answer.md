# 8.3 参考答案

memcheck 检查越界，racecheck 检查数据竞争，initcheck 检查未初始化读取，synccheck 检查同步事件。独立 ASC 在目标编译选项中启用 sanitizer；标准工程给 Kernel 添加插桩选项。

故障程序返回非零时，查看是否出现题目设置的诊断，并找到对应源码行。例如 memcheck 分支把 2048 个 float 的搬运长度改成 4096，工具会报告非法读写。

从 racecheck、initcheck、synccheck 中选一种，在两种工程中比较同类诊断，可复用 8.2 节的日志。记录关键诊断、源码行号和原因即可。

修复题切回 baseline，保持 memcheck 插桩开启。修复后应正常退出、输出 `test pass`，且原有越界诊断消失。两份日志分别位于 `build/standalone-memcheck/mssanitizer.log` 和 `build/repaired-memcheck/mssanitizer.log`。

msDebug 应实际命中断点，设备栈帧指向目标源码行；继续运行后正常结束并输出 `test pass`。仅设置断点还不算命中。第 5 题为错，不应自行用 `sudo chmod` 开放 `/dev/drv_debug`。平台调试开关未开启或权限不足时记为 `BLOCKED`，联系平台管理员处理。
