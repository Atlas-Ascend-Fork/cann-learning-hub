# 7.6 参考答案

单卡先运行 `run.sh --npus 1`，不需要配置 HCCN IP。确认 Ascend C RTC 计算、ACL+HCCL 通信、Device 0 和 `Correctness=PASS`。

一次 SpMV 的主要数据流是 Broadcast x → 各 rank 计算 local_y → AllGather y。各分片行数可能不同，AllGather 前用 padding 补齐长度，汇集后只取有效行。额外的误差和计时规约位于计算之外，应与这两个数据通信区分。

local SpMV launch-to-complete = 提交开销 + 同步等待，Synchronization 已在其中，不能再次加到 total。汇总字段使用每轮跨 rank 最大值的平均；各阶段的最慢 rank 可能不同，阶段最大值也不一定相加等于 total。

多卡为选做。比较时固定输入、预热和重复次数，记录每个 rank 的设备与误差，再计算总时间的加速比。运行脚本会打印 `results/run.XXXXXX`，到其中查看各 rank 日志。rank table 必须与设备数量匹配；生成器的参数为 `--server-ip`、`--device-ip` 和 `--output`，rank/device ID 按 IP 顺序生成。
