# 3.6 参考答案

## 行分配

按行均分 10 行给 4 个进程，一种分法是 `[0,3)`、`[3,6)`、`[6,8)`、`[8,10)`，分别处理 3、3、2、2 行。这是手算的行均分方案；程序按非零元数量分区，实际边界还取决于每行长度。

分到 0 行的进程仍须参加集合通信，否则其他进程可能一直等待。

## 运行与结果

在第 03 章目录打开终端，执行：

```bash
cd src/mpi_spmv
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_COMPILER=mpicxx
cmake --build build -j
mkdir -p results
mpirun -np 2 ./build/spmv_mpi --matrix U1 --warmup 1 --repeat 3 --csv results/U1_2p.csv
```

分别把进程数改为 1、4，同时把结果文件名改为 `U1_1p.csv`、`U1_4p.csv`；进程数不超过分配的 CPU 核心数。保存 CSV 和对应的 `.per_rank.csv`，检查绝对 L2 误差小于 `1e-6`。

## 负载差异

日志中 `nnz_balance_ratio=max_local_nnz/average_nnz`，理想值为 1。`load_imbalance=(max_compute-average_compute)/average_compute`，理想值为 0。从 `.per_rank.csv` 的 `compute_ms` 列取各进程的平均时间，再求最大值和平均值。汇总 `compute` 是逐轮最大值的平均，不能用它替换公式中的 `max_compute`。

行数相同不表示非零元数量相同；按非零元分区也可能受单个长行限制。

## 计时分析

矩阵分发只执行一次，单独记录；每轮 total 包含广播、计算和汇集，不包含轮首 Barrier。每个阶段取各进程的最大值，再对重复轮次求平均，各阶段最大值可能来自不同进程，因此不必相加等于 total。

例如某轮两个进程分别用时 2 ms 和 3 ms，整体需要等待较慢的进程，使用 3 ms 表示这一轮的时间。固定矩阵和重复次数，只改变进程数，观察通信增加是否抵消了局部计算减少带来的收益。
