03.04《反哺与结业》练习答案

1.（单选题）B
   解析：双流闭环的关键连接：推理流的实施专家拿到
   优化策略后：能直接实现 → 写 kernel；实现不出 → 查
   知识库命中模板；知识库也无 → **标记缺口，回流训练
   流**补充。A/C 与机制不符；D 是仓级门禁的职责，与
   缺口回流无关。

2.（简答）参考要点
   - 以"Compare 256B 注意事项"条目为例：它会被推理流
     Step 4 的实施专家（或任何写掩码逻辑的 Agent）在
     策略制定 → 实施之间用到：掩码 count 非 64
     倍数时静默截断，条目直接给出 ⌈count/64⌉×64 的
     修法；
   - 知识 > 流程复杂度：若这条知识不存在，流程要
     补偿就得加"每个 Compare 调用前强制人工核对"之类
     的检查步骤。复杂度只保护这一次；而一条知识入库
     后，下一轮同类算子全部自动受益（双流闭环的复利）；
   - 判据：你的条目是否让某个"每次都要人想起来"的
     检查变成"Agent 主动告知"的默认行为。

3.（编程实践·必做）从学员到贡献者 参考要点
   - 三段式自检：实测依据（注明日期/芯片/用例，可对照
     FACTS.md 或你自己的 03.02/03.03 记录）→ 策略（可执行
     的规则，非原则口号）→ 纪律（何时必须/禁止）；
   - 门禁验证：该 Skill 的 evals 合法 + `bash tests/
     run-tests.sh --fast` 全绿，两道门禁都过才具备
     提交资格；
   - 提交流程（02.03 八步全程适用）：fork → 分支 →
     约定式 commit → push → POST /pulls 建 PR →
     **GET 回查** source/target/state 逐项一致；
   - 五条红线对照：内容源于代码/diff（不臆造）、Issue↔PR
     双向关联落齐、禁止向目标仓发测试请求、写操作前
     确认（仅两次卡点）、PATCH 200 ≠ 成功必须回查；
   - 提交前自检：cannbot-skill-reviewer 九维（≥80 可
     入库；70-79 改后复审）。

4.（编程实践·选做）AI 边界评估 参考要点
   - 适合的判据示例（对照四条属性）：UT 用例补全，
     重复性高 + 验收标准明确（覆盖率阈值/golden 对拍）
     + 流程成熟 + 数据可得 → 四条全占，适合交给 Agent；
   - 不适合的判据示例：对外承诺的性能指标做决定，
     责任边界敏感 + 验收标准在合同侧不在代码侧 → 人
     主导，Agent 只做数据整理与草案；
   - ROI 三步走：① 试点选高频 + 有明确验收的小
     场景（两周内可评估）；② 双重验证标准 = 精度/
     质量门禁 + 加速比或效率指标，两者都过才算有效；
     ③ 推广条件写死（如"连续两轮试点零回归"），避免
     以"感觉好用"代替判据；
   - 呼应结业框架：三步走的每一步都在训练"把边界
     判断从体感变成机制"，这是本路径最后一件带走
     的能力。
