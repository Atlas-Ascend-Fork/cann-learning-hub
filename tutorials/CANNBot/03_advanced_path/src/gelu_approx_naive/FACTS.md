## 2. 失败机理（逐元素定位）

4 个失败用例的超差元素**全部为数值型**（负值带），非位置型：

| 用例 | 超差元素 | 超差 x 范围 | 最大 absdiff |
|---|---|---|---|
| L0-4 [4093] | 1/4093 | x=−3（尾部特殊值） | 1.378e-07 |
| L1-2 [256] | 1/256 | x=−5.118 | 1.021e-07（impl=−0，golden=−1.02e-07） |
| L1-3 [29] | 1/29 | x=−3（特殊值） | 1.378e-07 |

- 超差元素 100% 为负值；L1-1（正值带 [5,20]）与 L1-4（饱和区 \|x\|>20）**通过**。
- L0-4 唯一失败元素 idx=4085 是特殊值 x=−3（位于尾部 X_SPECIALS），**不是**对齐边界问题。
  该 kernel 无任何 Compare 调用，Compare 256B 截断对本工程**不成立**。

## 3. 误差分解（L2-5 负值带，CPU 模拟 + 真机对照）

| 变体 | 负值带超差 | 带内最大误差 | 说明 |
|---|---|---|---|
| 纯 8 步舍入累积（tanh 以 fp64 计算后仅一次舍入） | **0** | 7.675e-08 | 算法层预算紧张但未越线（裕量仅 23%） |
| np.tanh(fp32) 完整链 | 167 | 1.501e-07 | CPU 复现"代码没错但超差" |
| NPU naive（Tanh 向量指令） | 189 | 1.392e-07 | 指令近似误差更大 → 更多元素越线 |
| NPU sigmoid 恒等式修复 | 0 | —— | 消除函数近似误差，只剩最终舍入 |

**结论链**：
1. `z = 0.5·x·(1+tanh(y))` 在负值带（y≈−3~−9，tanh→−1）发生**抵消放大**：
   δ=1+tanh(y)≈1e-7~1e-4 是两个近似相等数之差，tanh 的绝对误差（≈ulp(1)）被相对放大；
   再乘 |x|≈3~5 → z 误差 1.4~3e-7，超过 atol=1e-7。
2. 纯累积（变体1）不越线但裕量仅 23%，**预算紧张是结构性前提**。
3. tanh 的**任何** fp32 实现（np.tanh 0.5ulp / NPU 指令 ~1ulp）都带绝对误差，
   经抵消放大后越线，差别只在越线元素数（167 vs 189）。
4. sigmoid 恒等式 `tanh(y)=2·sigmoid(2y)−1` 不含函数近似误差，最终舍入 0.5ulp
   → 带内最大误差 7.675e-08 < 1e-7 → 全绿。

## 4. 三坑归因（最终版，供册 08 引用）

| 坑 | 层次 | 内容 | 修复 | 回归（真机实测） |
|---|---|---|---|---|
| 坑 1 | **算法层** | 8 步链负值带预算紧张（裕量 23%）+ Step6 抵消放大结构；分段修复**不改变失败集** | 分段 \|x\|>6（Compare+Select，负侧 **0·x** 构造） | 失败集不变（4 败依旧）；饱和区（L1-4/L2-3）转为**构造性正确**（不再依赖 x³ 溢出/tanh 饱和语义） |
| 坑 2 | **API 约束层** | Compare/Compares count 模式 256B 对齐（fp32 需 64 倍数，**静默截断**）+ NaN 比较恒为假 | ⌈count/64⌉×64；EQ 自反比较 | xlog1py 真机实录走读（见 §5），非本工程 hands-on |
| 坑 3 | **指令层** | Tanh 向量指令近似误差 ~1ulp(1)，在紧张预算上越线（189 元素） | sigmoid 恒等式替代 | **14/14 全绿**（单独应用即全绿） |

**特殊值陷阱（坑 1 的隐藏考点）**：golden 参考链在 x=−Inf 处因 `Inf·0=NaN` 给出 **NaN**
（而非数学上的 0）；分段负侧若写字面 0 会导致 L2-2 **新失败**。用 `0·x` 构造：
有限负值→∓0（保号），−Inf→NaN，与 golden 语义精确一致（真机验证）。

## 5. 坑 2 实录出处（xlog1py 工作流，真机）

- `adv-operators-v3/.cannbot/xlog1py/workflow2/2-实现记录.md` §2.3：
  Compare/Compares count 模式约束（CANN 9.1.0 头文件实测依据），按
  `count×sizeof(T)/256` 整除分解 repeat，fp32 下 count 非 64 倍数时尾部元素被
  **静默丢弃**；工程对策：尾块计算数向上取整到 64 倍数、搬运仍按有效数。
- 同文件 §3（调试记录）：c220 vcmp/vcmpvs 对含 NaN 操作数的比较在**所有 CMPMODE
  下均返回 0**（非 IEEE unordered 语义），NE(y,y) 惯用法失效，须用 EQ 自反比较；
  该轮调试 5 例 NaN 失配 → EQ 重构 → 黑盒 22/22。
- `fix1_segmentation.diff` 中的 `computeCount` 64 对齐与 NaN→走计算链分支，
  即本实录经验在 gelu 分段修复中的直接应用。
