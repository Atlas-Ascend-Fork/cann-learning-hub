1. （单选题）v3.0.0 中，某节点验收失败后 harness 的处理是？
   答案：B

   解析：harness 按重试预算（默认 max_retries=3）自动重跑该节点，
   verifier 的失败原因（≤500 字符）由 harness 注入下一次执行的提示词。
   重试耗尽后才整轮退出交 PM 规划下一轮（省略可选节点、复用已验收
   产物）。A 是 v2 时代的行为（CP 门禁等人工确认）；C/D 均不是
   v3.0.0 的设计。

2. （单选题）“需求已确认，后续可以静默开发了”出现的时机与含义？
   答案：B

   解析：启动前问卷（repo-requirement Skill，≤5 题）答完后，PM 发出
   该提示，此后进入静默执行（运行中零交互），完成或阻塞时再汇报。
   这是 v3.0.0 边界静默设计的核心：决策集中在启动前和整轮退出后
   两个边界，中间完全放权。

3. （简答）节点 4 代码修复节点确认“仅注释差异”后，为什么不重跑
   全量测试而是复用节点 3 的设备证据？这体现了哪条设计思想？

   参考答案：

   代码修复节点（节点 4）的验收要求是"全量黑盒、白盒回归与代码检视
   通过"。当 verifier 用 AST 归一化（忽略注释/空白后比对代码结构）、
   token 级序列比对、位级 diff 三重独立验证确认代码变更仅为注释/
   docstring 修改（行为零变化）时，决定测试结果的全部输入（源码哈希、
   测试框架、阈值、环境）与节点 3 完全一致，重跑不会产生新信息，
   只会消耗设备时间。

   因此 verifier 选择复用节点 3 已生成的全量设备证据（构建日志、逐
   用例 PASSED 记录、证据清单），并在验收报告中记录复用依据。这体现
   了设计思想三过程与产物分离的核心价值：**证据可复用，重复劳动
   可避免**。多轮目录隔离保证了前轮证据的完整性与可追溯性。

   补充：如果变更涉及代码行为（非纯注释），则必须重新执行全量测试，
   不能复用旧证据。复用判定有严格的前提条件。
